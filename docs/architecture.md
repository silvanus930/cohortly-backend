# Architecture

Cohortly is a single NestJS application backed by PostgreSQL. It is deployed
as a stateless process (or several under PM2) in front of a database, an S3
compatible object store, an SMTP relay and Stripe.

## Request pipeline

Every request passes through the same chain, configured once in
`src/app.setup.ts` so that production and the e2e harness behave alike:

1. `helmet` security headers and CORS from `CORS_ORIGINS`.
2. Rate limiting through `@nestjs/throttler`, with tighter limits on
   sensitive auth endpoints.
3. `JwtAuthGuard`: every route requires a bearer token unless marked
   `@Public()`. The JWT strategy reloads the user so suspensions apply
   immediately.
4. `RolesGuard`: enforces `@Roles()` metadata; superadmins always pass.
5. `ValidationPipe` with whitelisting, so unknown fields are rejected and
   DTOs are transformed into typed instances.
6. Controller handler.
7. `ResponseEnvelopeInterceptor` wraps successes as
   `{ success, data, meta }`, hoisting pagination metadata. Handlers marked
   `@SkipEnvelope()` (for example the certificate SVG) return raw bodies.
8. `AllExceptionsFilter` turns every error into
   `{ statusCode, error, message, path, timestamp }` and maps Postgres unique
   and foreign key violations to 409 and 400.

## Modules

| Module          | Owns                                                                 |
| --------------- | -------------------------------------------------------------------- |
| `auth`          | registration, login, Google sign in, tokens, OTP reset, guards       |
| `users`         | user entity, admin management, analytics summary, referral codes     |
| `organizations` | organizations, memberships, invitations, seat packs, seat assignment |
| `courses`       | categories, courses, curriculum, assets, public catalog              |
| `storage`       | presigned uploads and server side uploads to S3 compatible storage   |
| `cohorts`       | cohorts, live sessions, waitlists, attendance                        |
| `enrollments`   | enrollment, lesson progress, streaks, completion handlers            |
| `quizzes`       | question banks, attempts, auto grading, lesson gating                |
| `assignments`   | submissions, rubric grading, cohort gradebook                        |
| `certificates`  | SVG certificates, verification, reissue                              |
| `payments`      | Stripe Checkout, webhook, purchases, refunds                         |
| `referrals`     | partner profiles, referral relationships, commissions, payouts       |
| `notifications` | in-app inbox                                                         |
| `mail`          | Nodemailer transports and email templates                            |
| `analytics`     | admin dashboards and instructor performance                          |

Modules communicate through services exported by their Nest module. Where a
dependency would run backwards (for example the catalog needing to know
about enrollments), the upstream module exposes a registration hook and the
downstream module registers a callback in `onModuleInit`:

```
catalog ----registerContentAccessResolver----> enrollments
cohorts ----registerJoinPolicy---------------> enrollments
progress ---registerLessonGate---------------> quizzes
enrollments -registerCompletionHandler-------> certificates
payments ---registerPaidHandler/RefundHandler> referrals
```

## Data

- PostgreSQL 16 through TypeORM 0.3 with `synchronize` disabled. Schema
  changes are hand written migrations in `src/database/migrations`.
- Ids are UUIDs generated by the database. Money is stored in integer minor
  units with an explicit currency column.
- Aggregations for dashboards run as SQL in the analytics module instead of
  loading rows into the process.

## External services

- **Object storage**: any S3 compatible store. Clients upload directly via
  presigned PUT urls; the API only signs requests and stores keys and public
  urls. Certificates are uploaded server side and also kept in the database.
- **Email**: Nodemailer with `smtp`, `log` or `memory` transports. Tests use
  `memory` and read the outbox to extract OTP codes and invitation tokens.
- **Stripe**: hosted Checkout plus a signed, idempotent webhook. See ADR 0002.

## Testing strategy

Unit specs live next to the code and mock collaborators. End to end suites
under `test/` boot the whole application against `cohortly_test`, apply
migrations, truncate tables and drive real HTTP requests through supertest.
CI runs both, with PostgreSQL provided as a service container.

## Operations

- `npm run build` compiles to `dist/`; `ecosystem.config.js` runs it under
  PM2 in cluster mode.
- `GET /api/v1/health` reports liveness and a database probe and returns 503
  when the database is unreachable.
- Configuration is validated on boot with Joi; a missing or malformed
  variable stops the process with a readable message.
